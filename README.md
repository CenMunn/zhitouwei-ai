# 智投委 AI

智投委 AI 是一个面向个人投资者、金融专业学生和投研人员的研究工作台。输入公司或研究问题后，可以从不同角度整理观点、展开投资辩论、查看研究结论并导出报告。对于需要逐项核对的财务问题，提供独立的 PDF 财报核验入口。

我们希望解决的是一个很具体的问题：模型可以很快给出分析，但使用者仍然需要知道数字从哪里来、是不是同一年、是不是同一张报表，以及结论有没有超出资料能说明的范围。因此，这个项目既保留多角色讨论，也把来源、计算、评分调整和报告留存接在了一起。

当前整理版本：2026 年 10 月 27 日。应用基于 10 月 18 日已部署的 `DeepSeekFlash-DecisionNewsFix-20261018` 版本；本次整理补齐了从空数据库启动的说明和公开股票目录初始化，没有重新训练模型或进行新的准确率评测。

## 可以做什么

| 模块 | 使用方式 |
| --- | --- |
| 研究工作台 | 输入公司或比较问题，查看行情、分析观点、辩论、风险及研究结论 |
| Agent 洞察 | 查看基本面、行业、宏观、量化、舆情等角色的评分和理由 |
| 评分复核 | 补充资料，生成待确认的评分候选；也可以填写理由后人工调整，保留修改历史 |
| 投资辩论 | 查看支持方、审慎方的论点、回应以及风控意见 |
| 研究报告 | 阅读较完整的分析，保存后重开，下载 Markdown 或通过浏览器打印为 PDF |
| 财报核验 | 导入带文本层的 PDF，围绕原页提问，检查来源、年度、范围、单位和计算 |
| 新闻 | 按公司获取公开新闻条目，显示时间、出处和原文链接，支持刷新 |
| 预测实验 | 使用随包提供的 LightGBM 模型和历史日线快照进行实验性预测展示 |
| 账户 | 注册普通用户、管理员管理、会话保存和记录归属控制 |

## 先运行起来

需要 Node.js 24.x 和 pnpm 11。源码包不包含已安装的第三方依赖、生产构建、模型服务密钥或原开发机数据库，第一次启动需要联网安装依赖。

### 1. 获取源码并安装依赖

```sh
git clone https://github.com/CenMunn/zhitouwei-ai.git
cd zhitouwei-ai
pnpm install --frozen-lockfile
```

如果使用 ZIP，完整解压后在含有 `package.json` 的目录打开终端即可，不必执行 `git clone`。

### 2. 配置模型和本地地址

Windows PowerShell：

```powershell
Copy-Item .env.example .env
```

macOS / Linux：

```sh
cp .env.example .env
```

在本机编辑 `.env`，填写自己的 `DEEPSEEK_API_KEY`。默认配置如下，密钥留空：

```dotenv
DATABASE_URL=file:./db/application.db
FILINGS_DATA_DIR=./db/filing-documents
PORT=3000
APP_ORIGIN=http://127.0.0.1:3000
APP_BIND_HOST=127.0.0.1
NEXT_TELEMETRY_DISABLED=1
FILINGS_PROVIDER=deepseek
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_API_KEY=
FILINGS_RETRY_POLICY=no_content_only
```

当前运行配置使用 `deepseek-flash`。实际可用的模型名称、调用额度和访问权限以自己的服务账户为准；如果服务端不接受该名称，应修改 `DEEPSEEK_MODEL`，不能靠修改页面上的模型名称解决接口错误。模型请求从服务器发出，密钥不需要放到浏览器里。

### 3. 初始化数据库和管理员

```sh
node tools/source-control.cjs init
```

这一步会生成 Prisma 客户端、建立 SQLite 表、创建本机管理员，并导入随包提供的 9,840 条公开股票身份记录。它们是代码、名称和市场等目录信息，不是实时行情。

首次生成的管理员用户名和随机密码保存在本机 `.local/admin-credentials.json`，请自行打开查看。这个文件不属于源码，也不要提交到仓库。普通用户可以在页面注册。重复初始化不会重置已有管理员密码；不要用重置数据库的方式处理登录问题。

### 4. 启动开发服务

```sh
node tools/source-control.cjs dev
```

打开 `http://127.0.0.1:3000/`。财报核验入口是 `http://127.0.0.1:3000/filings`。保持终端运行，按 `Ctrl+C` 停止。

### 5. 构建生产版本

```sh
node tools/source-control.cjs build
node tools/source-control.cjs start
```

生产构建默认写入 `.next-postreview`，启动器会复制静态资源和 PDF 解析所需依赖。源码里保留的原始 `pnpm start` 含有早期 Bun/Unix 写法，Windows 上请使用上面的交付启动器。

本地默认只监听 `127.0.0.1`。换端口时同时修改 `PORT` 和 `APP_ORIGIN`；部署到实际域名时，`APP_ORIGIN` 也应填写对应的完整网址。项目没有预置固定公网服务，临时隧道地址是否可用取决于运行它的主机。

## 建议怎样体验

1. 登录后，在研究工作台选择一家公司，提出一个明确问题，例如比较两家公司的经营现金流。
2. 查看各角色的判断、评分理由及资料范围，再看辩论与研究结论。
3. 发现资料不完整时，在评分复核处补充原文和来源；检查生成的候选后再确认，或按实际依据人工调整。
4. 打开研究报告，检查数据对照和来源附录，保存、刷新重开并下载 Markdown。
5. 在财报核验页导入财务原页 PDF，提问时写明公司、年度、合并或母公司口径、指标与单位。
6. 最后体验预测实验，留意页面上的样本日期、数据范围和模型限制。

财报上传支持带文本层的 PDF，单份上限 8 MiB、40 页。扫描件 OCR 没有作为本版已验证能力。整本年报太大时，先截取相关财务原页再导入。

## 系统怎样实现

前端使用 Next.js App Router、React、TypeScript 和 Tailwind CSS；后端接口与前端放在同一项目中。SQLite 通过 Prisma 访问，保存账户、研究会话、分析结果、辩论、报告和复核记录。

研究流程大体是：解析问题 → 收集财报、行情和新闻 → 多角色分析 → 论证与回应 → 风险审查 → 研究结论 → 保存与报告导出。运行中会记录阶段状态和调用情况，失败不会伪装成成功结果。

角色不是八个分别训练的大模型。它们通过不同职责、提示词、输入资料和输出约束分工，当前生成路径共用 DeepSeek 接口。模型负责生成候选分析、观点和文本；程序负责来源匹配、年度与报表范围检查、单位和计算校验、候选采用、保存与导出。这些规则能够发现部分错误，不能保证每一句自然语言判断都正确。

| 代码位置 | 主要内容 |
| --- | --- |
| `src/app` | 页面、登录注册和后端接口 |
| `src/components/research` | 洞察、辩论、结论、评分复核与报告界面 |
| `src/lib/ai` | 模型接口、角色提示、研究流程和新闻检索 |
| `src/lib/filings` | 财报解析、资料匹配、核验及报告相关逻辑 |
| `src/lib/auth` | 密码、登录会话与权限处理 |
| `src/lib/data` | 行情、公司新闻、股票身份目录和登记资料 |
| `src/lib/forecast` | 预测实验的特征和模型推断 |
| `prisma/schema.prisma` | 数据库表结构 |
| `public/forecast` | 导出的预测模型和历史行情快照 |
| `db/seed/universe.json` | 公开股票身份种子 |
| `scripts` | 构建辅助、账户初始化、预测训练和回归所需工具 |
| `tests` | 规则、接口契约、评分、导出等回归测试 |
| `tools` | 从空库初始化、构建和启动的辅助脚本 |

### 评分如何理解

角色分数采用 0—100 的投资吸引力表达，越高表示该角色在当前资料条件下越看好。它不是上涨概率，也没有校准成预期收益。显示评分时会同时说明资料、理由、置信度和人工修改情况。

默认角色权重为基本面 30%、行业 20%、宏观 10%、量化 20%、舆情 10%、风控 10%。有限资料下的估计和人工调整有降权规则；纯技术动量还会进一步降权；无有效置信度的基准值不参与综合评分，其余有效项归一化。具体实现见 `src/lib` 中的评分和复核逻辑。这是一套产品规则，目前没有证明这组权重能带来更高的交易收益。

补充资料后请求模型复核，不等于已经完成了人工审核。人工调分需要保留理由和实际登录身份，原评分及修改历史继续保留。新材料和最新新闻也不会静默改写已保存的历史报告，需要重新研究或明确执行复核。

### 预测实验与未来数据

预测模块使用 LightGBM 和日线特征，运行页面依赖 `public/forecast` 中已经导出的模型与数据，不需要先安装 Python。特征只使用指定日期及之前的行情，训练、验证和测试按时间划分，跨边界标签在实验中剔除。

保留的实验结果没有显示模型稳定胜过简单基线，也没有做出已盈利策略的承诺。历史快照推断不应当作实时交易信号。重做训练需要 Python、NumPy、pandas、LightGBM，以及训练脚本引用的原实验配置和锁定数据；本仓库保留训练代码，但不包含整套比赛评测与原始资料归档。

### 新闻与外部服务

公司新闻优先读取东方财富公开资讯，显示原始发布时间和链接；行情依赖外部行情源。外部接口可能限流、不可达或改变格式，刷新失败应查看错误信息，不能把“没有拿到数据”理解为“市场没有新闻”。历史代码还保留可选的外部检索支持，没有配置时不会假装检索成功。

## 检查与排错

```sh
pnpm test
pnpm run typecheck:app
```

本次整理重新运行了 552 项自动回归测试。它们用于检查程序规则与交互契约，不代表 552 道金融问题都回答正确，也不代表当前模型的独立准确率。比赛历史评测与本版模型、工作流不同，不能把历史数字直接当成本版能力。

| 遇到的问题 | 先检查什么 |
| --- | --- |
| 模型没有生成 | `.env` 中的密钥、模型名称、额度及服务器返回的错误码 |
| 数据库找不到或缺表 | 是否在项目根目录执行过 `node tools/source-control.cjs init` |
| 首页没有股票目录 | 初始化是否完成股票种子导入；可重新执行初始化，不要删库 |
| 保存或复核请求被拒绝 | 浏览器实际地址是否与 `APP_ORIGIN` 一致 |
| PDF 上传失败 | 文件是否有文本层、大小及页数是否合规；生产包是否完整执行构建辅助脚本 |
| Windows 提示 SWC 被阻止 | 查看系统应用控制策略，使用允许运行 Node/Next 工具链的环境 |
| 新闻为空 | 检查网络、公司代码和上游接口，确认是成功空结果还是请求失败 |
| 改完代码页面没变 | 生产服务需要重新构建后重启，历史报告则需要重新研究 |

## 数据和使用范围

仓库不放真实密钥、登录会话、私人运行数据库、上传文档或开发机配置。自己的数据会在初始化和使用过程中生成，默认位于 `db` 和 `.local`，已在 `.gitignore` 中排除。发布前不要把这些目录中的运行文件手工加回版本管理。

部分登记财报和行情快照用于演示与研究复现，使用时应核对原始出处、报告期和数据范围。目录覆盖不等于每家公司都有完整财报，自动核验也不能替代专业判断。项目提供研究辅助，不承诺投资收益。
